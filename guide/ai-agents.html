AI agents (MCP) ​

AI agents such as Claude, ChatGPT, Claude Code, Cursor and VS Code can read your Orbit, deploy and roll back applications, back up databases and write the wiki through the Model Context Protocol. Orbit serves it itself at /api/v1/mcp, so there is nothing to install on the server. An agent connects in one of two ways:

  • Signing in as you, for Claude.ai, ChatGPT and any agent that supports OAuth. You choose the workspaces and the most it may do, and it switches between those workspaces. See Sign in as yourself.
  • With an API token, for scripts and agents you configure by hand. The token belongs to one workspace. See Connect with a token.

What an agent can do ​

An agent acts like its token, or like you within what you allowed, under the same checks as the API: it sees only the tools of its role, and Orbit refuses anything the role cannot do.

Warnings, incidents, steps and failures reach the agent as text, written in English the way the console writes them, not as codes for the agent to interpret.

Restoring a backup over a database, deleting applications, databases or projects, and changing settings stay in the console. A wiki page an agent deletes only goes to the trash. An agent with the admin role writes the General wiki like a workspace admin does; with a lower role it only reads it. Moving a folder between collections stays in the console. An agent never opens a folder with a password: it sees that the folder is locked, not what is inside, and it cannot type or remove the password. A folder for owners and admins only is visible to an agent whose role is admin.

Actions wait for you ​

The tools marked after you confirm in the table, such as deploy_app, backup_now and create_project, take two calls. The first one does nothing: it answers what would happen, such as Deploy the image nginx:1.28 to the application shop; now it runs nginx:1.27, and a confirmation code. The agent shows you that summary, and only after you agree calls again with the code. The code:

  • works once, for two minutes;
  • only for the same agent, the same workspace and exactly the same arguments, so the agent cannot confirm one thing and run another.

The tools are also marked as actions, and destructive for deploys and rollbacks, so clients that ask before running tools ask you too. Orbit then records the action like any other, as Release bot (MCP · claude-code) or under your name, and the agent follows it with get_operation.

Sign in as yourself ​

Orbit is the OAuth server of its own MCP endpoint. An agent that supports OAuth only needs the address, your Orbit's address followed by /api/v1/mcp:

  • Claude.ai: in Settings → Connectors, add a custom connector with that address.
  • ChatGPT: with developer mode on, create a connector with that address and OAuth authentication.
  • Claude Code: claude mcp add --transport http orbit https://orbit.example.com/api/v1/mcp, then /mcp to sign in.

The agent opens an Orbit page in your browser. Sign in as usual, with your password, second factor, GitHub or Google. The page shows the account the agent will act as and the address it returns to; only allow it if you started the connection a moment ago. Then choose:

  • The workspaces it may use. It works in one at a time. It asks list_workspaces to see them and use_workspace to switch, and the choice stays for that connection.
  • The most it may do: viewer, developer or admin. It never acts above your own role in a workspace, and never manages members, tokens or credentials.

What it changes is recorded under your name with the agent next to it, such as Grace Hopper (MCP · Claude). Settings → Security → AI agents lists, under Connected AI agents, every agent connected to your account, with its workspaces and when it was last used. Disconnect stops it at once; the agent has to ask again to reconnect.

Orbit follows the MCP authorization specification: authorization code with PKCE (S256), dynamic client registration and the metadata at /.well-known/oauth-protected-resource and /.well-known/oauth-authorization-server. Access tokens last an hour and work only on /api/v1/mcp; refresh tokens last 60 days and change at every use.

Connect with a token ​

  1. In Settings → API tokens, create a token for the agent. A viewer token is enough to read; writing the wiki takes an admin token. Name it after where it runs, such as Claude Code on my laptop.
  2. Add Orbit to the agent with your Orbit's address followed by /api/v1/mcp, and the token in the Authorization header.

Settings → Security → AI agents has Connect an AI agent, which writes these lines for each agent. A token you just created under API tokens on that page is already in them, so you can copy them as they are.

Claude Code:

sh
claude mcp add --transport http orbit https://orbit.example.com/api/v1/mcp --header "Authorization: Bearer orbit_..."

Cursor, in ~/.cursor/mcp.json:

json
{
  "mcpServers": {
    "orbit": {
      "url": "https://orbit.example.com/api/v1/mcp",
      "headers": { "Authorization": "Bearer orbit_..." }
    }
  }
}

VS Code, in .vscode/mcp.json, which asks for the token instead of keeping it in the file:

json
{
  "inputs": [{ "type": "promptString", "id": "orbit-token", "description": "Orbit API token", "password": true }],
  "servers": {
    "orbit": {
      "type": "http",
      "url": "https://orbit.example.com/api/v1/mcp",
      "headers": { "Authorization": "Bearer ${input:orbit-token}" }
    }
  }
}

Claude Desktop only starts local programs, so it runs a small bridge, orbit-mcp, that passes its messages to your Orbit. Install it once; on a Mac with Apple silicon:

sh
sudo mkdir -p /usr/local/bin
sudo curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/orbit-mcp-darwin-arm64 -o /usr/local/bin/orbit-mcp
sudo chmod +x /usr/local/bin/orbit-mcp

Then add it to claude_desktop_config.json (in Claude Desktop, Settings → Developer → Edit Config) and restart Claude Desktop:

json
{
  "mcpServers": {
    "orbit": {
      "command": "/usr/local/bin/orbit-mcp",
      "env": { "ORBIT_URL": "https://orbit.example.com", "ORBIT_TOKEN": "orbit_..." }
    }
  }
}

Each Orbit release publishes the bridge for macOS (Apple silicon and Intel), Windows and Linux, listed in its signed SHA256SUMS; Connect an AI agent shows the commands for your computer. It works with any Orbit that has the MCP endpoint, so updating it is optional.

The bridge is not signed by Apple or Microsoft. Installed with the commands above, macOS runs it as is. Downloaded with a browser, macOS refuses to open it until you run xattr -d com.apple.quarantine /usr/local/bin/orbit-mcp, and Windows SmartScreen asks for confirmation the first time. To check a download, compare its SHA-256 with the line in the release's SHA256SUMS, whose signature Orbit verifies on every update.

A token belongs to one workspace; for another workspace, add Orbit again with that workspace's token, or sign in as yourself.

Safety ​

  • Only agents. The endpoint answers API tokens and agents that signed in as someone, never a console session or a request from the server itself. An agent's sign-in works only on the MCP endpoint, not on the rest of the API.
  • Every change is signed. What an agent changes is recorded with the token's name, or the person's, and the agent: a wiki page it writes shows Docs bot (MCP · claude-code) or Grace Hopper (MCP · Claude) as its author. Revoking the token or disconnecting the agent stops it at once.
  • Values stay in Orbit. An agent reads the names of an application's variables, never their values, and no tool answers a credential or a connection string. A value an agent sets goes through the conversation with the model, so type anything sensitive in the console instead.
  • Edits never overwrite. To edit a page the agent passes the revision it read; if someone changed the page since, Orbit refuses the edit and the agent has to read it again. Every revision stays in the page's history and can be restored.
  • Text is data. Logs, wiki pages, incident evidence and build output are text written by applications and people. Orbit marks them that way in each answer, and agents should never follow instructions found in them.
  • Answers are bounded. Logs come back at most 200 lines of at most 2,000 characters, pages at most 60,000 characters, and metrics as the latest 60 samples.
