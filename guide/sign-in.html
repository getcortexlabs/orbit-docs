Sign in with GitHub or Google ​

People can sign in to Orbit with GitHub or Google instead of a password. Orbit finds the account whose email the provider has verified, so it never creates an account on its own: someone without one needs an invitation first.

Setting it up ​

Each provider needs an OAuth app of your own. Orbit's administrator sets it up under Settings → Sign in with GitHub and Google, where Configure shows the callback URL to register, such as https://orbit.example.com/sign-in/github/callback.

  • GitHub: under GitHub → Settings → Developer settings → OAuth Apps, create a new OAuth app. Use the console's address as the homepage URL and the callback URL Orbit shows as the authorization callback URL. Copy the client ID, generate a client secret and save both in Orbit.
  • Google: in Google Cloud, under APIs & Services → Credentials, create an OAuth client ID of the Web application type and add the callback URL Orbit shows to its authorized redirect URIs. Save the client ID and secret in Orbit. Orbit asks for the openid, email and profile scopes.

The client secret is stored encrypted and is never shown again; saving without one keeps the one saved before. The callback URL follows the console's address: when that changes, register the new one with the provider.

Signing in ​

Continue with GitHub and Continue with Google appear on the sign-in page once a provider is set up.

  • Orbit asks the provider for the emails it has verified, GitHub's primary email first, and signs in to the account that uses one of them. An email the provider has not verified is never used.
  • With two-factor sign-in on, Orbit asks for the code after the provider, as it does after a password.
  • When no account uses those emails, the sign-in stops and says which email it got.
  • A sign-in has to finish within 10 minutes, and its link works once.

Invitations ​

An invitation can be accepted with Continue with GitHub or Continue with Google when the provider has verified the invited email. A new member joins without a password and signs in with the provider from then on; someone who already has an account joins with it.

Turning it off ​

Remove stops signing in with that provider. Sessions that are open stay open and passwords keep working. Members who joined through the provider have no password, so they cannot sign in until the provider is configured again.
