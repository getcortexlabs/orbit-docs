Agentes de IA (MCP) ​

Agentes de IA como Claude, ChatGPT, Claude Code, Cursor e VS Code podem ler o seu Orbit, fazer deploy e rollback de aplicações, fazer backup de bancos e escrever no wiki pelo Model Context Protocol. O próprio Orbit atende em /api/v1/mcp, então não há nada para instalar no servidor. Um agente se conecta de um destes dois jeitos:

  • Entrando como você, no Claude.ai, no ChatGPT e em qualquer agente com OAuth. Você escolhe os workspaces e o máximo que ele pode fazer, e ele alterna entre esses workspaces. Veja Entrar como você mesmo.
  • Com um token de API, para scripts e agentes configurados à mão. O token pertence a um workspace. Veja Conectar com um token.

O que um agente pode fazer ​

Um agente age como o token dele, ou como você dentro do que você permitiu, com as mesmas checagens da API: ele só vê as ferramentas do papel dele, e o Orbit recusa o que esse papel não pode fazer.

Avisos, incidentes, etapas e falhas chegam ao agente como texto, escritos em inglês do jeito que o console escreve, e não como códigos para o agente interpretar.

Restaurar um backup por cima de um banco, apagar aplicações, bancos ou projetos, e mudar configurações continuam no console. Uma página do wiki que um agente apaga só vai para a lixeira. Um agente com papel admin escreve no wiki Geral como um admin de workspace; com um papel menor ele só lê. Mover uma pasta entre coleções continua no console. Um agente nunca abre uma pasta com senha: ele vê que a pasta está trancada, não o que há dentro, e não pode digitar nem remover a senha. Uma pasta só de donos e admins aparece para um agente com papel admin.

As ações esperam por você ​

As ferramentas marcadas com depois que você confirma na tabela, como deploy_app, backup_now e create_project, levam duas chamadas. A primeira não faz nada: ela responde o que aconteceria, como Deploy the image nginx:1.28 to the application shop; now it runs nginx:1.27, e um código de confirmação. O agente mostra esse resumo para você e só depois que você concorda chama de novo com o código. O código:

  • funciona uma vez, por dois minutos;
  • só para o mesmo agente, o mesmo workspace e exatamente os mesmos argumentos, então o agente não consegue confirmar uma coisa e executar outra.

As ferramentas também são marcadas como ações, e como destrutivas no caso de deploy e rollback, então os clientes que perguntam antes de rodar ferramentas também perguntam para você. Depois o Orbit registra a ação como qualquer outra, como Release bot (MCP · claude-code) ou com o seu nome, e o agente acompanha com get_operation.

Entrar como você mesmo ​

O Orbit é o servidor OAuth do próprio endpoint MCP. Um agente com OAuth só precisa do endereço, o do seu Orbit seguido de /api/v1/mcp:

  • Claude.ai: em Settings → Connectors, adicione um conector personalizado com esse endereço.
  • ChatGPT: com o modo desenvolvedor ligado, crie um conector com esse endereço e autenticação OAuth.
  • Claude Code: claude mcp add --transport http orbit https://orbit.example.com/api/v1/mcp, e depois /mcp para entrar.

O agente abre uma página do Orbit no seu navegador. Entre como sempre, com senha, segundo fator, GitHub ou Google. A página mostra a conta com que o agente vai agir e o endereço para onde ele volta; só permita se você começou a conexão agora há pouco. Depois escolha:

  • Os workspaces que ele pode usar. Ele trabalha em um por vez. Ele pede list_workspaces para vê-los e use_workspace para trocar, e a escolha fica para aquela conexão.
  • O máximo que ele pode fazer: viewer, developer ou admin. Ele nunca age acima do seu próprio papel num workspace, e nunca gerencia membros, tokens ou credenciais.

O que ele muda fica registrado com o seu nome e o agente ao lado, como Grace Hopper (MCP · Claude). Configurações → Segurança → Agentes de IA lista, em Agentes de IA conectados, todos os agentes conectados à sua conta, com os workspaces e quando foram usados pela última vez. Desconectar para o agente na hora; ele precisa pedir de novo para voltar.

O Orbit segue a especificação de autorização do MCP: authorization code com PKCE (S256), registro dinâmico de clientes e os metadados em /.well-known/oauth-protected-resource e /.well-known/oauth-authorization-server. Os access tokens duram uma hora e só funcionam em /api/v1/mcp; os refresh tokens duram 60 dias e mudam a cada uso.

Conectar com um token ​

  1. Em Configurações → Tokens de API, crie um token para o agente. Um token viewer basta para ler; escrever no wiki pede um token admin. Dê ao token o nome de onde ele roda, como Claude Code no meu notebook.
  2. Adicione o Orbit ao agente com o endereço do seu Orbit seguido de /api/v1/mcp, e o token no cabeçalho Authorization.

Configurações → Segurança → Agentes de IA tem Conectar um agente de IA, que escreve estas linhas para cada agente. Um token que você acabou de criar em Tokens de API nessa página já vem nelas, para copiar como estão.

Claude Code:

sh
claude mcp add --transport http orbit https://orbit.example.com/api/v1/mcp --header "Authorization: Bearer orbit_..."

Cursor, em ~/.cursor/mcp.json:

json
{
  "mcpServers": {
    "orbit": {
      "url": "https://orbit.example.com/api/v1/mcp",
      "headers": { "Authorization": "Bearer orbit_..." }
    }
  }
}

VS Code, em .vscode/mcp.json, que pede o token em vez de guardá-lo no arquivo:

json
{
  "inputs": [{ "type": "promptString", "id": "orbit-token", "description": "Token de API do Orbit", "password": true }],
  "servers": {
    "orbit": {
      "type": "http",
      "url": "https://orbit.example.com/api/v1/mcp",
      "headers": { "Authorization": "Bearer ${input:orbit-token}" }
    }
  }
}

Claude Desktop só inicia programas locais, então ele roda uma ponte pequena, a orbit-mcp, que repassa as mensagens para o seu Orbit. Instale uma vez; num Mac com Apple silicon:

sh
sudo mkdir -p /usr/local/bin
sudo curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/orbit-mcp-darwin-arm64 -o /usr/local/bin/orbit-mcp
sudo chmod +x /usr/local/bin/orbit-mcp

Depois adicione em claude_desktop_config.json (no Claude Desktop, Settings → Developer → Edit Config) e reinicie o Claude Desktop:

json
{
  "mcpServers": {
    "orbit": {
      "command": "/usr/local/bin/orbit-mcp",
      "env": { "ORBIT_URL": "https://orbit.example.com", "ORBIT_TOKEN": "orbit_..." }
    }
  }
}

Cada release do Orbit publica a ponte para macOS (Apple silicon e Intel), Windows e Linux, listada no SHA256SUMS assinado; Conectar um agente de IA mostra os comandos para o seu computador. Ela funciona com qualquer Orbit que tenha o endpoint MCP, então atualizá-la é opcional.

A ponte não é assinada pela Apple nem pela Microsoft. Instalada com os comandos acima, o macOS a executa normalmente. Baixada pelo navegador, o macOS se recusa a abri-la até você rodar xattr -d com.apple.quarantine /usr/local/bin/orbit-mcp, e o SmartScreen do Windows pede confirmação na primeira vez. Para conferir um download, compare o SHA-256 dele com a linha no SHA256SUMS do release, cuja assinatura o Orbit verifica em toda atualização.

Um token pertence a um workspace; para outro workspace, adicione o Orbit de novo com o token daquele workspace, ou entre como você mesmo.

Segurança ​

  • Só agentes. O endpoint atende tokens de API e agentes que entraram como alguém, nunca uma sessão do console ou uma requisição do próprio servidor. A entrada de um agente só funciona no endpoint MCP, não no resto da API.
  • Toda mudança é assinada. O que um agente muda fica registrado com o nome do token, ou da pessoa, e o agente: uma página que ele escreve mostra Docs bot (MCP · claude-code) ou Grace Hopper (MCP · Claude) como autor. Revogar o token ou desconectar o agente para ele na hora.
  • Valores ficam no Orbit. Um agente lê os nomes das variáveis de uma aplicação, nunca os valores, e nenhuma ferramenta responde uma credencial ou uma string de conexão. Um valor que o agente define passa pela conversa com o modelo, então digite o que for sensível no console.
  • Edições nunca sobrescrevem. Para editar uma página, o agente informa a revisão que leu; se alguém mudou a página desde então, o Orbit recusa a edição e o agente precisa ler de novo. Toda revisão fica no histórico da página e pode ser restaurada.
  • Texto é dado. Logs, páginas do wiki, evidências de incidentes e saída de build são textos escritos por aplicações e pessoas. O Orbit marca isso em cada resposta, e agentes nunca devem seguir instruções encontradas neles.
  • Respostas têm limite. Logs voltam com no máximo 200 linhas de até 2.000 caracteres, páginas com até 60.000 caracteres e métricas com as 60 amostras mais recentes.
