DNS na Cloudflare ​

Com a Cloudflare conectada, o Orbit cria sozinho os registros DNS dos domínios próprios, então um domínio numa das suas zonas passa a ser roteado e ganha certificado em segundos, sem nada para copiar. Os previews de pull request também podem abrir num domínio seu.

Conectando a Cloudflare ​

Na Cloudflare, abra My Profile → API Tokens → Create Token e dê ao token estas permissões nas zonas que o Orbit deve cuidar:

  • Zone: Zone: Read, para listar as zonas;
  • Zone: DNS: Edit, para criar e apagar registros.

Depois cole o token em Configurações → Integrações → Conectar Cloudflare.

  • O Orbit confere o token antes de guardá-lo. Ele lista as zonas ativas e, em cada uma, cria e apaga um registro TXT chamado _orbit-check. Um token que a Cloudflare não aceita, ou sem alguma das permissões, é recusado com uma mensagem que diz qual falta.
  • Zonas que o token só consegue ler aparecem como só leitura. Os domínios nelas continuam funcionando do jeito manual.
  • Onde o token fica: selado no cofre de segredos do Orbit, nunca mais exibido e nunca escrito nos logs. Ele vai junto no orbit backup.
  • Zonas adicionadas depois aparecem sozinhas: o Orbit relê as zonas do token no máximo uma vez por minuto. Ele olha as primeiras 50 zonas ativas.

Um token para todos os workspaces ​

Em vez de um token por workspace, um administrador da instalação pode conectar um só em Configurações → Sistema → DNS na Cloudflare para todos os workspaces, com as mesmas permissões. Cada zona passa a listar os seus workspaces: ative os que devem vê-la e editá-la. Um workspace só alcança as zonas que recebeu, então quem for convidado para um workspace nunca mexe nos domínios de outro.

  • Uma zona nova fica sem workspace até você atribuí-la. Quando a instalação tem um único workspace, conectar atribui todas as zonas a ele.
  • Um workspace com token próprio continua usando o dele e ignora o compartilhado. O card dele em Configurações → Integrações diz qual token está em uso.
  • Trocar o token mantém as atribuições das zonas que ele ainda alcança. Desconectar esquece o token e as atribuições; os registros que o Orbit criou continuam na Cloudflare.
  • Tirar uma zona de um workspace mantém funcionando os registros que o Orbit já criou nela, mas o Orbit deixa de atualizá-los para aquele workspace.

Adicionando um domínio ​

Adicione o domínio em Domínios da aplicação, como sempre. Quando o nome cai numa zona editável (vence a zona mais longa que combina), o Orbit:

  1. cria os registros que a página do domínio pediria: um registro A para cada servidor recebendo tráfego, num domínio raiz, ou um CNAME para o endereço gerado, num subdomínio, com o proxy da Cloudflare desligado;
  2. marca esses registros com o comentário Orbit <id do domínio>, para alterar e remover depois apenas os próprios registros;
  3. verifica o domínio na hora e passa a roteá-lo, e o Let's Encrypt emite o certificado por HTTP.

O cartão do domínio diz Os registros DNS ficam na Cloudflare, com a zona.

  • Registro já existente: o Orbit não mexe nele até você aprovar uma revisão. Se ele aponta para outro lugar, o console cadastra o domínio sem mudar o DNS e abre Configurar DNS automaticamente. Confira os registros atuais e propostos, autorize a substituição e aplique. Você pode cancelar e continuar configurando o DNS manualmente.
  • Servidores mudam: quando um servidor passa a receber tráfego ou deixa de receber, o Orbit atualiza os registros em até 30 segundos. Quando a Cloudflare recusa uma mudança, o cartão mostra o motivo e o Orbit tenta de novo cinco minutos depois.
  • Remover o domínio apaga os registros dele na Cloudflare.

Deixe o proxy desligado enquanto o Orbit cuida dos registros: o Orbit compara o endereço resolvido com os dos servidores, e o Let's Encrypt valida por HTTP. Os domínios servidos pelo Cloudflare Tunnel são a exceção: o Orbit liga o proxy para eles.

Corrigindo um domínio existente ​

Em Domínios da aplicação, escolha Configurar automaticamente num domínio próprio. O Orbit identifica quem hospeda o DNS pelos nameservers, incluindo subdomínios delegados; pode ser uma empresa diferente daquela onde você comprou o domínio.

Esta primeira versão configura a Cloudflare. Se precisar, conecte o token na própria janela, com as permissões acima. Ele precisa poder editar a zona responsável pelo domínio. DigitalOcean, GoDaddy e Squarespace são identificados quando seus nameservers são reconhecidos, mas continuam com instruções manuais por enquanto.

A revisão mostra os registros atuais ao lado dos propostos. Substituir ou assumir registros A, AAAA ou CNAME existentes exige autorização explícita. O Orbit confere tudo de novo antes de aplicar; se algo mudou, pede uma nova revisão. Só os registros de endereço revisados desse nome são substituídos, numa única operação em lote da Cloudflare. Outros nomes e registros de e-mail são preservados. Se o CNAME proposto entrar em conflito com MX, TXT ou outro registro no mesmo nome, a configuração automática é bloqueada e a janela explica o motivo.

Depois de aplicar, o domínio aguarda a verificação do DNS e depois do HTTPS. Registros com proxy de um Tunnel são confirmados consultando novamente a Cloudflare, conferindo o destino e se pertencem ao Orbit, porque o DNS público retorna os endereços da Cloudflare. Só aceitar a requisição não faz o HTTPS aparecer como ativo. Se a conexão cair durante a alteração, abra uma nova revisão antes de tentar de novo.

Após a aprovação, o Orbit cuida dos registros que cria: mudanças nos servidores atualizam esses registros, e remover o domínio também os apaga.

Previews no seu domínio ​

Em Previews de um projeto, dê aos previews um domínio numa zona editável, como preview.example.com. O Orbit então:

  • cria um registro A wildcard, *.preview.example.com, para cada servidor recebendo tráfego, marcado e mantido em dia como os registros dos domínios próprios;
  • pede ao Let's Encrypt um único certificado wildcard, *.preview.example.com, provando que a zona é sua com um registro TXT (DNS-01). Para isso, o cert-manager guarda uma cópia do token no namespace cert-manager do cluster; o certificado fica em orbit-previews, e o Traefik o entrega a todos os previews;
  • abre cada preview novo em pr-<número>.preview.example.com. As outras aplicações do mesmo preview ficam em <aplicação>-pr-<número>.preview.example.com.

Um preview novo responde em HTTPS assim que é publicado, sem esperar certificado.

  • Previews abertos: o domínio só pode ser definido, trocado ou removido sem nenhum preview aberto, para todos os previews de um projeto terem o mesmo tipo de endereço. Feche-os antes.
  • Um registro wildcard criado por outra pessoa para esse nome e apontando para outro lugar é recusado, mostrando o registro que a Cloudflare tem.
  • Remover o domínio apaga o registro wildcard e o certificado, e os previews voltam a usar sslip.io.

Desconectando ​

Desconectar Cloudflare esquece o token e apaga a cópia dele no cluster. Os registros que o Orbit já criou continuam na Cloudflare e funcionando; o Orbit para de mudar ou apagar esses registros, e quando um domínio precisa de registros diferentes, a página dele lista o que adicionar à mão. O certificado dos previews continua valendo até expirar, uns três meses depois de emitido, mas não é renovado.
