Bitbucket ​

O Orbit faz build e deploy a partir do Bitbucket Cloud, com deploy no push e previews de pull requests, do mesmo jeito que faz a partir do GitHub. O Bitbucket Data Center não é suportado.

Conectando o Bitbucket ​

Em Configurações → Integrações → Conectar o Bitbucket, ou ao escolher Bitbucket num projeto novo, informe ao Orbit:

  • O ID do workspace, como em https://bitbucket.org/<workspace>/.
  • Um token de acesso desse workspace: um token de acesso de workspace alcança todos os repositórios dele, um de projeto os de um projeto, e um de repositório um repositório só. Dê a ele estas permissões:
    • Repositories: Read, para listar e ler os repositórios e cloná-los nos builds;
    • Webhooks: Read and write, para adicionar os webhooks que publicam no push;
    • Pull requests: Read, opcional, para os pull requests chegarem ao Orbit e ganharem previews.

Um token sem as duas primeiras é recusado com uma mensagem que diz qual escopo falta. Sem a terceira, os pushes publicam mas os pull requests não ganham preview; as Configurações dizem isso.

  • Onde o token fica: ele é selado no cofre de segredos do Orbit, nunca mais é mostrado e nunca vai para os logs. Ele vai junto no orbit backup.
  • Cada workspace do Orbit conecta o seu próprio workspace do Bitbucket.

Escolhendo um repositório ​

Num projeto novo, escolha Repositório Git e depois Bitbucket. O Orbit lista os repositórios que o token consegue ler, os atualizados mais recentemente primeiro. Escolha um e uma branch, e o Orbit lê a branch pela API do Bitbucket para detectar como fazer o build e rodar, como faz com o GitHub. A importação de Compose também lê um compose.yaml de um repositório do Bitbucket.

Os builds clonam com git. O Bitbucket não deixa tokens de acesso baixarem o arquivo de um commit, então o Orbit busca o commit com o git do servidor principal, autenticado com o token. O Ubuntu Server já vem com o git; num servidor sem ele, instale-o (apt-get install git) antes de publicar a partir do Bitbucket, ou o build falha dizendo isso.

Deploy no push ​

Quando uma aplicação é criada a partir de um repositório do Bitbucket, o Orbit adiciona um webhook nesse repositório. Ele envia pushes, e pull requests quando o token consegue lê-los, para https://orbit.<ip-do-servidor-com-traços>.sslip.io/bitbucket/webhook/<workspace>, assinados com um segredo que só o seu servidor conhece (X-Hub-Signature).

  • Uma entrega sem assinatura, ou com uma assinatura errada, é recusada.
  • Um push na branch de uma aplicação publica aquele commit quando Publicar automaticamente está ligado nas configurações da aplicação.
  • A mesma entrega enviada duas vezes publica uma vez.
  • Configurações → Integrações lista o webhook de cada repositório, ou por que ele não pôde ser adicionado.

Previews de pull requests ​

Os previews seguem as mesmas regras do GitHub: ligue-os em Previews do projeto, e cada pull request aberto a partir de uma branch de um repositório que o ambiente de origem publica ganha um preview, publicado de novo a cada push e removido com os seus dados quando o pull request é mesclado ou recusado.

  • Forks: pull requests de forks nunca ganham preview, então código de fora do repositório nunca roda nos seus servidores.

Desconectando ​

Desconectar o Bitbucket remove os webhooks que o Orbit adicionou e esquece o token. As aplicações mantêm a sua origem e podem ser conectadas de novo depois, mas deixam de publicar no push.
