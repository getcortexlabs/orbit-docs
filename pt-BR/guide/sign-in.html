Entrar com GitHub ou Google ​

As pessoas podem entrar no Orbit com GitHub ou Google em vez de uma senha. O Orbit encontra a conta cujo e-mail o provedor verificou, então ele nunca cria uma conta sozinho: quem não tem conta precisa antes de um convite.

Configurando ​

Cada provedor precisa de um app OAuth seu. O administrador do Orbit configura em Configurações → Entrar com GitHub e Google, onde Configurar mostra a URL de retorno para registrar, como https://orbit.exemplo.com/sign-in/github/callback.

  • GitHub: em GitHub → Settings → Developer settings → OAuth Apps, crie um novo OAuth app. Use o endereço do console como homepage URL e a URL de retorno que o Orbit mostra como authorization callback URL. Copie o client ID, gere um client secret e salve os dois no Orbit.
  • Google: no Google Cloud, em APIs e serviços → Credenciais, crie um ID de cliente OAuth do tipo Aplicativo da Web e adicione a URL de retorno que o Orbit mostra aos URIs de redirecionamento autorizados. Salve o client ID e o secret no Orbit. O Orbit pede os escopos openid, email e profile.

O client secret é guardado criptografado e nunca mais aparece; salvar sem ele mantém o que já estava salvo. A URL de retorno acompanha o endereço do console: quando ele muda, registre a nova no provedor.

Entrando ​

Continuar com GitHub e Continuar com Google aparecem na página de login quando um provedor está configurado.

  • O Orbit pede ao provedor os e-mails que ele verificou, o principal do GitHub primeiro, e entra na conta que usa um deles. Um e-mail que o provedor não verificou nunca é usado.
  • Com o login em dois fatores ligado, o Orbit pede o código depois do provedor, como faz depois da senha.
  • Quando nenhuma conta usa esses e-mails, o login para e diz qual e-mail recebeu.
  • Um login precisa terminar em 10 minutos, e o link dele funciona uma vez.

Convites ​

Um convite pode ser aceito com Continuar com GitHub ou Continuar com Google quando o provedor verificou o e-mail convidado. Um membro novo entra sem senha e daí em diante entra pelo provedor; quem já tem conta entra com ela.

Desligando ​

Remover para o login com aquele provedor. As sessões abertas continuam e as senhas continuam funcionando. Membros que entraram pelo provedor não têm senha, então só conseguem entrar quando o provedor for configurado de novo.
